What changed and why

None of the ADP skills and ADP reference documents read for this proposal mentions the User Guide. This proposal carries the guide inside each issue's contract, using pieces ADP already has, with no new skill.

  1. The issue names the guide. A Help docs: line in the issue, and two guide criteria in the contract. The planner only acts on what the issue says, so the guide has to be stated there.
  2. A page → guide map. One small data file linking each app page to its guide. Whoever writes the issue can miss a guide without it.
  3. A linked guide issue. The guide change is its own issue in the User Guide repo. ADP works in one repository per run.
  4. A reviewer checks the guide. A review criterion asks whether the guide change covers the page. The guide is judged with the code, not after it.
  5. The issue cannot close without the guide. A post-merge criterion waits for the guide pull request to be merged. Today a forgotten guide goes unnoticed.
