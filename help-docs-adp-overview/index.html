Help docs and ADP: the whole picture

How the help docs are kept up to date today, how ADP works, and how to make the help docs part of ADP.

Where we are

  • The work-issue pipeline keeps the help docs up to date. It is in use today.
  • ADP is the pipeline meant to replace it. It is also in use today.
  • ADP has no step for the help docs. An issue shipped through ADP can leave the help docs behind.

Where we want to be

  • Updating the help docs is part of ADP.
  • No new skill. The requirement travels inside each issue, using pieces ADP already has.
  • An issue cannot close until its help docs change is published.

Rules of ADP that matter here

  • An issue is built against its contract, and checked against it afterwards.
  • ADP works in one repository per run.
  • ADP never merges into the main branch. A person releases.
  • Only adp-qa closes an issue, and not while a criterion is unmet.

Help docs in ADP today

  • No ADP skill mentions the help docs.
  • Some ADP runs include the Help docs statement anyway, because the agent also reads the rules of the Clara Studio repository. Two such runs were found.
  • No ADP skill writes the help docs change, opens the docs PR, or checks that it was merged.
  • From step 1 to step 2: the client approves the scope, then a person runs the adp-plan-project skill.
  • Without Project Intake: any issue in Clara Studio can start at step 2 with the adp-plan-issue skill.
  • Maturity: ADP is defined by 24 documents and 11 skills. Only 4 of the 24 documents are approved; the rest are drafts.

3How to make the help docs part of ADP

The idea: do not add a skill. State the help docs in the issue, so ADP's own contract and checks carry them. Five pieces are needed.

  1. 1The issue names the help docs. It includes the Help docs statement, and its contract gets two help docs criteria.
  2. 2A page to guide map. One small file linking each app page to its guide, so no guide is missed.
  3. 3A linked help docs issue. The help docs change is its own issue, run by ADP in the help docs repository.
  4. 4A reviewer checks the help docs change together with the code, through a review criterion.
  5. 5The issue waits for the help docs. A criterion keeps it open until the docs PR is merged.
PhaseWhat changesResult
1. By handNothing in ADP. Whoever writes the issue adds the Help docs statement and the two criteriaWorks issue by issue. Nothing enforces it
2. EnforcedOne paragraph in the Protocol, one of the 14 ADP reference documentsADP refuses to plan an issue that changes what users see and lacks them
