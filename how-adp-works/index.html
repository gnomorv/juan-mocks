How ADP works

  • What it is: the Autonomous Dev Pipeline (ADP) takes a piece of work from an idea to merged, checked code.
  • Who does what: agents plan, build and check. A person approves at fixed points and merges.
  • What it is made of: 11 skills. A skill is a written set of instructions for one stage, which an agent follows step by step.
  • Where it is recorded: on the issue in Clara Studio: a comment for each step, the approvals and the results.

3The steps, in order

Plan

Step 1Prepare the repository

Skill: adp-setup

  1. The skill reads the repository to find the commands for tests, coverage and build.
  2. It shows the proposed profile. A person confirms it or changes its values.
  3. It saves the profile on its own branch and runs the checks once, to prove the profile works.

It runs once for each repository. Every later skill reads the profile to know which commands to run.

Step 2Turn the project into issues

Skill: adp-plan-project

  1. The skill finds the estimate of the project and checks that it is final and approved.
  2. It says what it is about to file.
  3. It files one epic, or one for each release, and one placeholder story for each line of the estimate.

A placeholder story is a rough story. It is planned in detail later.

Step 3Plan the epic

Skill: adp-plan-epic

  1. The skill sets the list of stories, their order and which story depends on which.
  2. It writes the epic plan: the objective, what the stories share, the scope and the tests that prove the stories fit together.
  3. Reviewers read the plan.
  4. The skill plans the first story in full. The other stories stay as placeholders.

Later stories are planned one at a time, when their turn comes, against the work already finished.

Step 4Plan the issue

Skill: adp-plan-issue

  1. The skill reads the issue and sizes it. If the issue is too big, it proposes a split.
  2. It writes the contract and saves it as the description of the issue.
  3. If the change shows on screen, a mock-up is agreed.
  4. Product, architecture and security reviewers read the contract.

Every issue passes through this step. No code is written before the contract is approved.

A personapproves the contract at the plan gate. The issue moves to Ready for Dev.
Build

Step 5Build the issue

Skill: adp-issue

  1. Tests first. One test is written for each point of the contract. Each test must fail first.
  2. Code. The smallest change that makes the tests pass. The tests are not edited at this step.
  3. Gate. Every check of the repository runs. A failed gate goes no further.
  4. Second look. The tests are checked for gaps. If the change shows on screen, a person sees the screenshots and says whether they look right.
  5. Review. Architecture and security reviewers read every change.
  6. Simplify. The change is made smaller without altering what it does.

The work is split between roles, so that no role checks its own work: one writes the tests, another writes the code, others review.

Step 6Open the pull request

Skill: adp-pr

  1. The skill brings the branch of the issue up to date with the shared code.
  2. If that changed reviewed files, they are reviewed again.
  3. It opens the pull request and waits for the automatic checks.
  4. It hands the pull request to a person. The skill itself never merges.
A personmerges the pull request.
Close

Step 7Check and close

Skill: adp-qa

  1. The skill looks for proof of each point of the contract. A comment that only says a point is met does not count.
  2. It posts one result comment on the issue.
  3. It moves the issue once: closed or ready for release when every point is met, back to development with a bug when one is not, blocked when proof is missing.

The skill does not check work it built itself.

5Keeping the work moving

OrderSkillWhat it does
1adp-groomSorts every open issue into four groups: ready, needs planning, needs a person, stale. It writes one report of what people owe.
2adp-dispatchReads that report and starts the work: planning for the issues that need a plan, building for the issues that are ready. It never starts the same issue twice.
3adp-queueWorks through the issues assigned to a person with nobody present, one at a time. For each one it starts adp-issue, waits and records the result.

Written from the text of the 11 ADP skills as read in Clara Studio on November 25 and 26, 2026. It describes what the skills say, not a watched run. The skills still change.

How to read this

One page that follows a piece of work through the pipeline, in the order things happen.

  1. Three phases and a backlog. Plan, Build, Close, with three skills that keep the list of work in order. The colours of the diagram are the colours of the steps below.
  2. Nothing is built without an approved plan. The contract comes first. Every later check is made against the contract.
  3. Tests before code. A test must fail before the code that fixes it is written. It proves the test really checks the point.
  4. People hold the approvals and the merge. The agents stop and wait at each of these points.
