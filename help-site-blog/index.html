What changed and why

Today the Clara Learning help site has the blog turned off (blog: false), so release notes, announcements and tips have no home. The proposal turns on the blog that comes with Docusaurus, set up the way its documentation recommends. No plugin to add. Posts, people and numbers here are placeholder content. Try it: select a post title or "Read more", then go back.

  1. Blog link in the top navigation. {to: '/blog', label: 'Blog'} next to Guides. The Docusaurus setup step: a blog/ folder plus one navbar item.
  2. "Recent posts" sidebar. The newest five posts, grouped by year. Built in (blogSidebarCount, default 5). Set it to 'ALL' to list every post.
  3. Date and reading time on every post. The date comes from the file name, blog/2026-11-10-release-notes.md. showReadingTime: true. One naming pattern for every file keeps the order right.
  4. Authors with name, role and picture. Defined once in blog/authors.yml and referenced by key in each post. Global authors can each get an author page listing their posts (page: true).
  5. Tags from a fixed list. blog/tags.yml holds Release notes, Announcements, Tips, Search, Connectors. With onInlineTags: 'throw' a typo in a tag fails the build instead of creating a new tag.
  6. Short summaries with "Read more", and feeds. Each post ends its summary with {/* truncate */}; RSS and Atom feeds are generated. The site parses Markdown strictly (future: v4), so the HTML-comment form <!-- truncate --> breaks the build. onUntruncatedBlogPosts: 'warn' catches posts with no marker. People can follow releases from a feed reader.
