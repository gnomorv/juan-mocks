What changed and why

The proposal opens the Documents tab as one tree: every shelf of the owner with its documents beneath, so you see the whole set without opening folders one by one. Today the tab opens as a list of one folder at a time, and the tree is offered on project pages only. Use Library / Workspace / Project in the bar to see the same tree at each level. Click a chevron or a folder row to fold a shelf; the Grid and List views still work.

  1. The tab opens in the tree, with every shelf expanded. All folders and documents of the owner show at once, indented 20px per level with dashed guide lines, and the toolbar reads "All folders" instead of Back, Forward and the folder path. Today the tab opens in List view at the top level, so seeing what a project holds means opening each folder and coming back. The tree answers "what is in here?" in one look.
  2. The same tree at every level: organization library, workspace and project. The Tree button sits beside Grid and List on all three. Today Tree is offered on project pages only, so the library and the workspace, which hold the shared material, are the ones you can't see whole.
  3. Projects are filed on numbered shelves. 1. Intake, 2. Design, 3. Delivery, 4. Handover, then Client material for what the client sends. Shelves are ordinary folders; the number makes them sort in the order a project is lived, and numbers sort naturally, so 10 comes after 9. The order of the folders now tells you where a project stands, and every project reads the same way.
  4. A chevron folds a shelf; clicking the folder row does the same. Folding is remembered while you stay on the page. A long shelf, such as the intake templates in the library, can be closed without leaving the tree.
  5. Rows show names only. No coloured type box beside a document's name, no status badge on any node, and no folder emoji in the tree: the chevron marks a folder and its name is in semibold. The names are what you scan. A type box or a badge on every row competed with them, and a status belongs beside the tree, in a column or a panel, not on the node.
  6. The Type column is plain text, and empty for folders. Each document's type is written out in 12/300; folder rows leave it blank. Today the column mixes coloured pills with a bold amber "Folder", the loudest word in the row.
  7. The counts cover the whole tree. The line under the list counts every folder and file of the owner. In the tree there is no "current folder", so a count of one folder would be wrong.
  8. Kept as they are. The header, the tabs, the three create buttons, the Modified, Created and Size columns and the "Indexing…" hint read as today; only the proposed type roles are applied. Grid and List view work as today. This mock-up is about the tree, not the rest of the page.
