Frequently Asked Questions

Document Info · User Guide · All Clara Studio users

Select a question to see the answer. Each answer links to the guide that covers it in full.

5

Getting started3

What is the difference between a workspace and a project?4

A workspace groups everything for one client or team. A project lives inside a workspace and holds the issues, documents and conversations for one piece of work. See Workspaces and Projects.

Where do I start after I sign in for the first time?

Open the Dashboard. It shows the workspaces you belong to and the issues assigned to you. Common Workflows walks through the first tasks most people do.

How do I find something I use often?

Star it. It appears under Starred in the sidebar. Stars are personal and don't affect what others see. See Starred.

Issues and projects

How do I see only the issues assigned to me?

Open My Issues. It lists every issue assigned to you across all workspaces, filterable by status or project. See My Issues.

Can I move an issue to another project?

Yes. Open the issue, select ⋯ → Move to project, and choose the destination. Comments and history move with it.

What happens to the issue's labels?

Labels that exist in the destination project are kept; the others are removed.

Conversations with Clara

Does Clara remember earlier conversations?

Each conversation keeps its own history, and Clara can read the documents and issues of the conversation's project. See Conversations.

Can I share a conversation with a teammate?

Conversations inside a project are visible to its members. Conversations started from the Dashboard are private to you.

Connecting tools

How do I use Clara from Claude Code?

Connect the Clara MCP server and sign in when asked. Steps: Connect Clara MCP to Claude Code. The server address looks like https://clara.example.com/mcp.

Account and access

Why can't I see a workspace a teammate mentioned?

You only see workspaces you're a member of. Ask the workspace's admin to add you.

What changed and why

Today the Clara Learning help site has no FAQ: quick questions are answered somewhere inside the long section guides, so people ask in chat instead. The proposal adds one FAQ page built the way the Docusaurus documentation recommends for collapsible content: plain <details> and <summary> in Markdown, which Docusaurus styles itself. No plugin and no custom component. Questions and answers here are placeholder content. Try it: open and close the questions.

  1. FAQ link in the top navigation. Next to Guides, System Reference and Connect Clara. One click from any page; today the only entry points are the guides themselves.
  2. FAQ is the last item of Start Here. One file, help-site/docs/faq.md, plus one line in sidebars.ts under Start Here. The sidebar is explicit, so a page not listed there appears in no menu. Start Here is where new users already look.
  3. Questions are grouped under normal headings. Getting started, Issues and projects, Conversations, Connecting tools, Account and access. Headings sit outside the collapsibles, so they appear in the "On this page" table of contents and have links of their own.
  4. Each question is a <details> block; the summary stays on one line. Answers can hold links, lists, code and even a nested question. Docusaurus's own tip: a line break inside <summary> makes MDX add extra paragraphs. Built-in styling means the page matches light and dark themes with no CSS. The site's strict-MDX rules (no bare { }, no HTML comments) still apply.
  5. Expand all / Collapse all (optional). A small client component. Useful once the list grows; also makes the browser's find-in-page work across every answer. Not needed for a first version.
  6. A way out when the answer is missing. A footer line pointing to the support channel. Unanswered questions become the next FAQ entries.
