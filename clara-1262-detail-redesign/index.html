What changed and why

The workspace and project detail pages share one skeleton: the project's general fields mirrored onto the workspace, the same rollup and table components, stage readiness at the centre of the project, and a recency feed. Use Workspace / Project in the bar to switch pages, and click a note to open its tab. Live pages: nine workspace tabs and seven project tabs in different orders; the proposal does not cover the Questions, Engagement, Scope and Updates sections that today's project page shows on support projects.

  1. Both pages · tab rowOne tab order on both pages. Overview, the work tab (Projects or Issues), Documents, Conversations, Activity, Connectors, then Settings; the workspace adds Assets before Settings. Today the two tab bars differ in order and length, so the same tab is in a different place on each page.
  2. Both pages · OverviewThe same rollup on both pages. A title, an Open board link, the counts and a status bar; every number and bar segment opens the board already filtered to that status. One component to learn and maintain, and the summary becomes a way in rather than a dead end.
  3. Workspace · OverviewThe project's general fields are mirrored onto the workspace. Description and Notes (a new workspace field) sit in the main column; deal and next-step fields are left out because they don't apply to a workspace. The two overviews read alike, and what someone knows about the client has a place to live.
  4. Workspace · Overview railThe rail leads with the internal owner, then the external contact. Account owner and Primary contact are new workspace fields, in the same order as the project's Assignee and Contact; Key facts adds Status, Industry and Website. Contacts belong in the rail, never in the top strip, and both pages answer "who owns this, who do we talk to" in the same spot.
  5. Workspace · Projects tabProjects and Issues share one skeleton. Header with the create action, rollup, toolbar (search and filter), table, pager. The filter differs on purpose: state chips here, Show closed on Issues. Issues hand detailed filtering to the board; projects have no board, so they filter here.
  6. Workspace · Activity tabA light recency feed, not a full audit log. Recent conversations, document updates and issue and project changes, gathered from the workspace's projects. Workspaces have no event store of their own; this gives the workspace an Activity tab so its tabs line up with the project's.
  7. Workspace · Connectors tabConnectors stay as they are. They ship from the connectors work already on dev; the redesign only places the tab. No reason to redesign something that just landed.
  8. Workspace · Assets tabAssets are left as they are until the connectors migration reaches production. Name and description only, after the shared tabs. Their integrations already live on Connectors, so redesigning Assets now would create two competing places for the same thing.
  9. Project · OverviewStage readiness leads the project overview. The same component as the sales pipeline: required document types (Project Scope, Business Requirements, Solution Design) gate advancement, SOW is optional. Click a stage to open it. Whether a project can move to its next stage is the most important thing on it, and both surfaces should show it the same way.
  10. Project · Overview railDeal fields collapse after the sale. Click Deal to open it; empty fields stay hidden. Delivery work isn't taxed with sales fields nobody edits any more.
  11. Project · Issues tabIssues get a header with the create action. "+ Add issue" reassigns an existing issue rather than creating a duplicate; the rest follows the Projects skeleton. Tick Show closed to see closed issues. Every list tab now starts the same way: title, count, primary action.
  12. Project · Documents tabThe same stage requirements on the Documents tab. Requirements are met by the project's own documents; linked workspace documents no longer count. The tab where documents are made shows what still has to be made.
  13. Project · Conversations tabOrigin conversations stay, read only. The sales-lead conversations sit under the project's own, dimmed. They are provenance: useful context, not ongoing work.
