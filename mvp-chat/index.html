ETL Pipeline Specification

Spec · Analytics Hub

Overview

This specification defines the ETL pipeline that consolidates subscription data from two payment providers into WarehouseDB.

Data sources

  • PayCo: subscription events via webhooks, with hourly reconciliation polling
  • AppMart: server-to-server notifications plus daily reports

Pipeline architecture

A workflow scheduler orchestrates three stages:

  • Extract: pull raw events into an object-storage staging area
  • Transform: normalize to one subscription schema
  • Load: upsert into the WarehouseDB analytics tables

Data model

Each subscription event has subscriber_id, provider, plan_id, status, mrr, event_timestamp, provider_metadata.

Success criteria

  • Under 15 minutes of latency for webhook events
  • 99.9% accuracy against the source systems
  • At least 100k events a day

What this proposes and why

The first MVP of Clara Studio as a chat: you pick what the conversation is about, ask Clara for something, watch the tools she calls, and get the document she wrote in a side panel. There is no form to fill in.

  1. Pick the conversation's scope first: Global, Client or Project. The header badge follows the choice. What Clara can see and change depends on scope, so it is set before the first message, not guessed from it.
  2. The sidebar tree is the context. Client › asset › project, each project with one of three states: Draft, Active or Closed. "+" asks Clara to create a client. Choosing a project in the tree is how you tell Clara what you are working on.
  3. Clara shows her work as tool cards. Each card names the tool and its arguments, says Done or Created, and opens to show the raw result. People can check what Clara looked at before trusting what she wrote.
  4. What Clara creates comes back as a card in the chat. Title, type, when, and a one-line summary. The result of the conversation is visible where it happened, not hidden in another list.
  5. The document opens in a side panel over the chat. From "View full spec" or the Documents button in the header. You read the spec without losing your place in the conversation.
  6. Next steps are offered as quick replies. Create estimate, Revise scope. The usual follow-ups are one click away, and they show what Clara can do next.
