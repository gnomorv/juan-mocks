Project Intake, ADP and the Help Docs

How they connect today, and where the gap is.

In short

  • Project Intake feeds ADP today. Intake ends with a signed ticket plan, and a person starts ADP from it.
  • The help docs are the gap. No Project Intake skill and no ADP skill mentions them, so work shipped through ADP has no help-docs step.
  • A proposal closes that gap inside ADP. It is on its own page: User Guide updates with ADP.
Exists works today, according to the skills and the workflow documents Gap nothing covers this today Outside ADP done by a person, because ADP does not do this step

ADP is the Autonomous Dev Pipeline. Project Intake is the chain of skills that takes a client request to a signed scope.

1How it works today

Read from top to bottom. The left column is the work in Clara Studio. The right column is what happens to the help docs at the same moment.

Project Intake8 steps, one approval each

A client request becomes signed documents

Exists Scope, requirements, a mock when screens change, solution design, estimate, then the client signs off.

  • The estimate ends with a ticket plan.
  • Intake creates no tickets.

The intake skills do not mention the help docs.

↓The client signs off.
A person runs adp-plan-project.
ADP · Planfrom ticket plan to contract

The ticket plan becomes issues

Exists ADP reads the intake documents and refuses to start without the sign-off.

  • adp-plan-project files one epic and one placeholder story per line of the ticket plan.
  • adp-plan-epic splits the epic into stories.
  • adp-plan-issue turns each issue into a testable contract.

Second door: small work skips intake. Any Clara issue can start at adp-plan-issue.

The gap

Gap None of the 11 ADP skills mentions the help docs.

  • An issue can be planned, built and checked with no guide change.
  • Some runs add a Help docs: line anyway, because of a rule in the repo. Nothing enforces it.
  • A forgotten guide goes unnoticed.

Nothing checks that a guide was published.

2The older path has a help-docs step

The pipeline that ADP is meant to replace does carry the help docs. This is the step that has no counterpart in ADP yet.

MomentSkillWhat it does for the help docs
Plan/work-issueThe plan states Help docs: <guides> or Help docs: none, <why>
Pull request/prOpens the guide pull request first, then the code pull request
Merge to dev/mergeLeaves the guide pull request open
Release/production-releaseMerges each open guide pull request whose issues all shipped

The rule: a change needs a help-docs update when it alters what a person sees or does. Internal refactors, tests and pipeline changes do not.
