Project Intake, ADP and the Help Docs

What Clara Studio has today, and what needs to be added so the help docs stay up to date.

What we have today

  • Project Intake hands over to ADP. Project Intake ends with a client-approved estimate that contains a Ticket plan. A person then starts ADP, and ADP creates the issues from that Ticket plan.
  • The work-issue pipeline, which is not ADP, has help docs steps for each change. They were set up on November 11, 2026, and two changes have used them so far. Its plan includes the Help docs statement, it opens a docs PR next to the Clara Studio pull request, and the production release merges that docs PR.
  • ADP has no step for the help docs. Some ADP runs include the Help docs statement, but only because the agent also reads the rules of the Clara Studio repository.

What we need to add to ADP

  • Require the Help docs statement in every ADP issue that changes what users see or do.
  • Write the help docs change and open its docs PR.
  • Keep the issue open until its docs PR is merged.

How to add them: User Guide updates with ADP.

Help docs while ADP plans, builds and checks an issue

Exists Already there

  • The Clara Studio repository has a written rule: the plan of an issue must include the Help docs statement.
  • That rule was written for the work-issue pipeline. No ADP skill repeats it.
  • Some ADP runs include the Help docs statement anyway, because the agent also reads the rules of the repository. Two such runs were found.

To add Not there yet

  • No ADP skill requires the Help docs statement. Whether an ADP issue has one depends on the agent, not on ADP.
  • No ADP skill writes the change to the help docs.
  • No ADP skill opens the docs PR, or has it reviewed with the code.
Exists

To add

ADP does not check that the docs PR was merged before it closes the issue.

  • From step 1 to step 2: the client approves the scope, then a person runs the adp-plan-project skill. That skill refuses to create issues without the client's approval.
  • Without Project Intake: small work does not need it. Any issue in Clara Studio can start at step 2 with the adp-plan-issue skill.

3Help docs steps in the work-issue pipeline (this is not ADP)

This table does not describe ADP. It describes the work-issue pipeline, a separate and earlier set of skills that is still in use.

It is shown here because these are the help docs steps that exist today. ADP has none of them yet.

They apply to one change at a time, and exist since November 11, 2026. Nothing re-checks the guides already written.

MomentSkill of the work-issue pipelineWhat it does for the help docs
Plan/work-issueThe plan of the issue includes the Help docs statement
Build/work-issueThe same agent edits the guide in the help docs repository
Review/prThe review before the pull request reads the help docs change together with the code
Pull request/prOpens the docs PR first, then the Clara Studio pull request, and links the two
Merge to dev/mergeMerges the Clara Studio pull request and leaves the docs PR open
Production release/production-releaseMerges each open docs PR whose issues all shipped

The rule: a change needs a help docs update when it alters what a person sees or does. Internal refactors, tests and pipeline changes do not.
