Project Intake, ADP and the Help Docs

What we have today, and what we need to add.

What we have today

  • Project Intake feeds ADP. Intake ends with a signed ticket plan, and a person starts ADP from it.
  • The older pipeline updates the help docs. Its plan names the guide, the guide change travels with the code, and the release publishes it.
  • A written rule asks every plan to name the guide. Some ADP runs follow it, because the agent reads the repo's rules. ADP itself does not ask for it.

What we need to add

  • ADP asks for the guide. Every issue that changes what users see names the guide to update.
  • ADP writes the guide change. Today nothing in ADP does.
  • ADP checks the guide was published before it closes the issue.

How to add them: User Guide updates with ADP.

ADP is the Autonomous Dev Pipeline: the skills that plan, build, check and close an issue.

Project Intake is the chain of skills that takes a client request to a signed scope.

The Help docs: line is one line in a plan. It names the guides a change must update, or says "none" and why.

While ADP plans, builds and checks

Exists Already there

  • A written rule in the Clara Studio repo: a plan must carry the Help docs: line.
  • The rule was written for the older pipeline, not for ADP.
  • Some ADP runs write the line anyway, because the agent reads the repo's rules. Two such runs were found.

To add Not there yet

  • ADP does not ask for the line. None of its 11 skills includes the help docs, so the line appears by chance.
  • Nothing in ADP writes the guide change.
  • Nothing in ADP reviews the guide change with the code.
Exists

The guide is published

The release step merges the guide pull requests that someone opened.

To add

A check that the guide was published before the issue closes.

  • From step 1 to step 2: the client signs off, then a person runs adp-plan-project. ADP refuses to start without the sign-off.
  • Second door: small work skips Project Intake. Any Clara issue can start at step 2 with adp-plan-issue.

2The older path has a help-docs step

The pipeline that ADP is meant to replace does carry the help docs. This is the step ADP can take over.

MomentSkillWhat it does for the help docs
Plan/work-issueThe plan states Help docs: <guides> or Help docs: none, <why>
Pull request/prOpens the guide pull request first, then the code pull request
Merge to dev/mergeLeaves the guide pull request open
Release/production-releaseMerges each open guide pull request whose issues all shipped

The rule: a change needs a help-docs update when it alters what a person sees or does. Internal refactors, tests and pipeline changes do not.
