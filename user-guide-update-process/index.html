How a change in Clara Studio updates the User Guide

Every change that alters what a user sees opens two pull requests: one for the app and one for the User Guide. The guide is published the day the change reaches production.

Example used below: the feature "Add a button".

What changed and why

Today the guide text already travels with each change and is published at release. Four pieces are proposed to close what that leaves out.

  1. A page → guide map. One small file linking each app page to its guide. Today the agent picks the guides from an index and can miss one.
  2. The agent takes the screenshot. The image is re-captured with the text, in the same pull request. Today images are taken by hand, so they fall behind the text.
  3. A check after each release. Each touched page is compared with its last approved version. Today nothing looks at the pages once a release is out.
  4. Undocumented changes get reported. A difference becomes a guide update, or an issue when no ticket explains it. Today a change nobody wrote down goes unnoticed.
